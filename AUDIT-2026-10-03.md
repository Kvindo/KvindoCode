## 1. CRITICAL — the secret subsystem has corrupted the user's vault and is blinding the agent

**S1. The live vault is full of false positives and is only growing.**
`~/.kvindocode/secrets.vault.json`: 47 entries, `excludedSha256` empty, **14 entries longer than 500 characters**
(up to 5306 — whole tool outputs), **8 entries of 12 characters or fewer**. Entries are auto-created by the
auditor and look like `audited-<type>-<sha12>`; two values are stored under four different type-derived names
(`…-31258f3f59d0` appears as `token`, `api_key`, `credentials_in_url`, `private_key`) because the
tool-output path does not dedupe by SHA.

**S2. `IsFalsePositive` rejects almost nothing** — `Llm/AuditingLlmClient.cs:138-150`.
It filters out `$…`, `%[ $…$ ]%`, `<…>`, 32-128-char hex, GUIDs and `^[A-Z_][A-Z0-9_]*$` (SCREAMING_CASE
only). Every other token ≥7 characters is treated as a secret, so **identifiers are vaulted as credentials**:
`old_string`, a CamelCase API type name, the word `password`, `authenticationheader`-style names, a 35-char
URL fragment, etc. Confirmed against the vault by hashing the candidate strings.

**S3. `Resolve` promotes the auditor's 8-char quote to a whole word** — `AuditingLlmClient.cs:123-136`.
The auditor deliberately returns only the first 8 characters of a value; this code then takes the entire
whitespace-delimited run that contains that quote as "the secret". One sloppy quote → an identifier, a
sentence word or a URL fragment becomes a stored secret.

**S4. Masking then rewrites ordinary text everywhere, including the code the model reads.**
Stored values are replaced with markers by `SecretPlaceholders.Protect` on every `Read` line
(`Tools/FileTools.cs:157`), by `ProtectRequest` on every outbound request (`AuditingLlmClient.cs:189-199`) and
by `AgentSession.Mask`/`MaskToolCalls` on every event and tool argument (`Agent/AgentSession.cs:388-455`).
Consequences seen live in this session and reproducible:
* `Read` returns masked source — the model sees `%[ $audited-…$ ]%` instead of the real word in files it reads,
  and the marker text itself is what it then reasons about.
* Concrete damage: `Edit`'s own argument key `old_string` is masked in tool-call arguments
  (`AgentSession.cs:442-449`) and in the side panel (`Views/RightPane.cs:143` reads `S("%[ $audited-…$ ]%")`),
  and the secret-policy prose in `--password`-style flags in `SystemPrompt.cs:55,59` is masked — so the model
  is taught a corrupted version of its own tool contract.
* Because masking is applied to already-masked text, the vault now contains **nested markers** in entry
  *names* (a name containing another `audited-…` marker) — the masking pipeline is not idempotent.

**S5. Whole tool outputs are stored as "secrets" and then hidden from the model** — `AgentSession.cs:1064`:
```csharp
if (candidates.Count == 0 && r.Output.Length > 6) candidates.Add(("audited-output", r.Output));
```
When the auditor flags a tool result but no boundary resolves, the **entire** result (up to the 6000-char audit
gate) is vaulted as `audited-output-<sha>`; from then on that text is masked in the transcript *and* in the
context sent to the model. The agent goes blind to content it just read and starts looping. This is what
produced the 14 giant entries in S1 (`audited-audited-output-*`, 404-5306 chars, from Bash/Grep/Read).

**S6. The user has no way to correct any of this.** `IUserInteraction.ConfirmSecretAsync` is implemented
(`App/Services.cs:16`) and `SecretVault.Exclude`/`IsExcluded` exist, but **nothing in `src` calls either** —
grep finds only `tests/SecretExclusionTests.cs`. `excludedSha256` is empty. There is no UI to delete/purge
auditor entries either (the Secrets window lists them, but the only escape is manual deletion of each entry).

**S7. A failed read silently wipes the vault — and the settings.**
`SecretVault.LoadFileOnly` (`Secrets/SecretVault.cs:178-189`) catches everything and returns an empty
`VaultFile`; the next `Create/Set/Delete` calls `SaveFile()` and overwrites the real file with only the new
entry. `AppSettings.Load` (`Settings.cs:72-81`) has the same shape, and `AgentSession.cs:900-902` calls
`_settings.Save()` **on every model call**, so one transient read error (or a concurrent write) replaces
`settings.json` — API key, project list, model tags — with defaults, and then keeps writing it. No backup, no
atomic write, no error surfaced.

**S8. A missing `secrets.key` silently mints a new key** (`SecretVault.cs:79-99`) and every existing entry
becomes undecryptable. `HasUnmaskedValues` exists for exactly this case but no UI consults it, so the vault
just looks empty.

**S9. The auditor only ever sees the tail of the conversation.**
`Collect` (`AuditingLlmClient.cs:103-116`) audits **only the last message**, with content truncated to 1500
chars, each tool argument to 500, 6000 total. A secret further down a long pasted file, or in an older
message, is never scanned. `AuditImageAsync(..., "image/png")` (`:57`) hardcodes the MIME type, so JPEG/GIF/
WebP images are sent to the auditor with the wrong data URL. `Tool.SecretArgs` exists only on `SecretsTool`, so
a credential typed into a Bash command or Write content leaves the machine if the auditor misses it.

**S10. Debug logging left in the streaming path** — `Llm/LlmClient.cs:209`: every usage JSON object is appended
to `~/.kvindocode/usage-debug.log` unconditionally (the file is 1.5 MB / 4231 lines and never rotated/truncated),
on every completion of every request.

**S11. The Write tool refuses (or silently expands) marker-shaped text** — `Tools/FileTools.cs:200`.
`SecretPlaceholders.TryExpand` runs over all Write content: an *unknown* marker aborts the whole write
("Unknown or unavailable secret placeholder …: No secret named …" — I hit this twice trying to write this
report), and a *known* marker is silently replaced by the plaintext secret. So documentation that mentions the
marker syntax cannot be written, and round-tripping masked Read output through Write/Edit is lossy.

## 2. HIGH

**H1. `SecretRedactor.Contains` fails open** — `Secrets/SecretRedactor.cs:46`: it returns `false` as soon as the
text contains `%[ $`, and it is the gate for masking tool-call arguments (`AgentSession.cs:450`) and for
dropping images that accompany a secret (`:1081`). A call that contains a marker *and* a real value elsewhere
is not masked at all — a fail-open in a security control.

**H2. `Paths.EncodeProject` is not injective** — `Paths.cs:27` maps every non-alphanumeric character to `-`, so
`/a/b-c`, `/a/b/c` and `/a/b/c/` are the same project directory. Both the transcripts (`~/.kvindocode/projects/…`)
and the memory directory (`Paths.MemoryDir`, one `MEMORY.md` per project) collide; two unrelated projects
silently share one agent memory.

**H3. `ProjectContext.ReloadMemory` mis-implements its byte cap** — `Context/ProjectContext.cs:78-79` slices
`text[..Math.Min(text.Length, MemoryIndexMaxBytes)]`: a *character* count against a *byte* budget, so with
Cyrillic the loaded index can be ~4× the intended 25 000-byte limit.

**H4. `SubagentManager.Spawn` leaks the child on failure** — `Agent/Subagents.cs:42-69`: `child.Dispose()` is
only reached on the success path; if the child throws (not cancels), its `AgentSession`, `BackgroundTaskManager`,
`BrowserSession` and event subscriptions leak. The `ct` passed in is also ignored when already cancelled.

**H5. `HeadlessRunner` crashes on a trailing flag** — `Agent/HeadlessRunner.cs:33-34`: `cwd = args[++i]` /
`model = args[++i]` throw `IndexOutOfRangeException` for `kvindocode -p x --cwd` (no bounds check).

**H6. Every finished turn is flagged "needs attention"** — `MainWindow.axaml.cs:410`: the `TurnEndEvent` handler
adds the session to `_settings.AttentionSessions` regardless of how the turn ended (error, interrupt, blocked,
empty response). Nothing removes it except explicit dismissal, so the list becomes noise.

**H7. `settings.json` is rewritten per model call** — `AgentSession.cs:900-902` (token counters). Write
amplification on every round-trip, and a last-writer-wins race with the Settings window (`SettingsWindow` saves
the whole object).

**H8. `AuditingLlmClient.ProtectRequest` drops request metadata** — `:189-199` rebuilds `LlmRequest` without
`SessionId` and `AuditSecrets` (both `init`), so the sanitized request silently loses the per-session policy.

**H9. A malformed tool-call argument string can abort the turn** — `AgentSession.MaskToolCalls`
(`:442`) calls `JsonNode.Parse(c.Arguments)` outside any try/catch; truncated/invalid arguments (exactly what
`argsMaybeTruncated` is designed to handle gracefully at `:1024`) instead throw, propagate out of the loop and
surface as "Unexpected error" instead of the intended actionable message.

## 3. MEDIUM

* `SecretVault.RedactionTargets` requires length > 6 (`:344`) while `SecretRedactor.MinLength` is 6 with `>=`
  semantics (`SecretRedactor.cs:13`) — the two disagree about what is maskable.
* `SecretStream.Feed` (`SecretRedactor.cs:132-152`) calls `_buf.ToString()` per streaming delta and rescans
  every secret × every suffix length: quadratic work inside the token stream, made worse by 47 entries.
* `AgentSession.Replay` (`:519-529`) computes the "not shown" notice from a counter that advances for non-`msg`
  entries too, so the number in the notice is wrong.
* `MainWindow.RunSearchAsync` rebuilds the whole sidebar on a 250 ms timer while hits stream in, and
  `RebuildTranscript` re-creates the full transcript view on every rewind — UI-thread cost on long sessions.
* `HookRunner.RunAsync` (`Hooks/Hooks.cs:111`) runs async hooks in a bare `Task.Run` with
  `CancellationToken.None`: an exception there is unobserved and the hook outlives the cancelled turn.
* `CdpConnection.SendAsync` (`Browser/Cdp.cs:68-84`) creates a `Task.Delay` and a cancellation registration per
  call, and `ChromeLauncher._conn` is a process-wide static that is never disposed on exit.
* `ToolContext.Resolve` (`Tools/Tool.cs:22-26`) performs no containment check, and Regular mode has no
  permission prompts by design — so every tool can touch any absolute path the user can. Combined with S4/S11
  (masked text written back) this is how a bad round can damage files outside the project.
* `Settings.Save()` (per H7) is called from the agent loop, and `AppSettings.Save` writes via `File.Move(tmp,
  …, true)` — atomic per se, but with no backup and no guard against `Load` having returned defaults (S7).
* `ClaudeStorage.SaveMeta` (`Agent/ClaudeStorage.cs:160-205`) is a read-modify-write of the Claude desktop
  registry guarded only by its own lock; a concurrent write from the Claude app is silently lost.
* `DocumentReaders` shells out to `pdftotext`, `pdfinfo`, `convert`, `identify`, `file` with a hand-rolled PATH
  lookup and (for `convert`) no output-size guard.
* `VpnBypass.Describe` returns an "Enabled" status on non-Linux while `ActiveBypassInterface` silently returns
  null there.
* `Paths.IsUnder` uses ordinal comparison; on a case-insensitive filesystem the plan-mode write containment
  (`PlanFiles.IsWritableInPlan`) could be bypassed by case differences.
* `SessionStore.ReadHeader` reads only the first 40 lines but then prefix-matches later lines for titles
  (`{"kind":"title"`), which depends on serializer property order.
* `README.md` claims "96 tests"; the suite currently runs **149** and the document also quotes behaviour that is
  now stale (e.g. it does not mention the vault-poisoning risk or the concurrent-edit workflow).

## (original) 5. Suggested order of work

1. **Stop the bleeding (S1, S2, S3, S5, S6):** reject identifier-shaped and low-entropy tokens in
   `IsFalsePositive`, never vault a whole tool output (`AgentSession.cs:1064`), dedupe by SHA, and add a
   one-click "purge auditor false positives" action so the current 47 entries can be cleaned.
2. **Make the masker safe (S4, H1, S11):** make `Protect` idempotent and marker-aware, gate on `TryRedact`
   instead of `Contains`, never mask inside the app's own tool schema/prompt strings, and make `TryExpand`
   treat unknown markers as a warning instead of a write failure.
3. **Stop silent data loss (S7, S8, H7):** fail loudly on an unreadable vault/settings, write a `.bak` before
   overwriting, and move `_settings.Save()` out of the per-call path.
4. **Correctness fixes (H2-H6, H9):** project-dir encoding, memory byte cap, subagent disposal, headless arg
   bounds, attention-list semantics, `JsonNode.Parse` guard.
5. **Hygiene (S10, H8, plus the README/test-count drift).**
